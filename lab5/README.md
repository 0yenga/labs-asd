# Лабораторная работа №5

## Вариант 1. Хэширование

- ключ: СНИЛС;
- хэш-функция: функция деления;
- метод разрешения коллизий: метод цепочек.

Реализованы поиск, вставка, удаление, печать таблицы и рехэширование при
увеличении размера данных. Готовые коллекции JDK не используются: таблица —
это массив, а цепочки — односвязные списки.

## Ввод

Программа читает команды со стандартного ввода:

```text
insert <СНИЛС> <ФИО>
search <СНИЛС>
delete <СНИЛС>
print
help
exit
```

СНИЛС можно вводить с дефисами и пробелом, например `123-456-789 00`.
Программа оставляет только 11 цифр.

Пример:

```text
insert 123-456-789 00 Иванов Иван Иванович
insert 987-654-321 00 Петров Пётр Петрович
insert 111-222-333 44 Сидоров Сидор Сидорович
insert 123-456-789 07 Петров Пётр Петрович
insert 555-666-777 88 Смирнова Анна Сергеевна
print
insert 222-333-444 55 Кузнецов Илья Олегович
print
search 123-456-789 00
delete 987-654-321 00
print
exit
```

Перед шестой вставкой в ячейке 2 видна цепочка из ключей `12345678900`
и `12345678907` (оба дают остаток 2 при делении на 7). Шестая вставка
вызывает рехэширование: таблица увеличивается с 7 до 17.

## Запуск

```bash
javac -encoding UTF-8 -d out src/*.java
java -Dfile.encoding=UTF-8 -Dstdin.encoding=UTF-8 -Dstdout.encoding=UTF-8 -cp out Main < input.txt
```

В PowerShell:

```powershell
cmd /c "java -Dfile.encoding=UTF-8 -Dstdin.encoding=UTF-8 -Dstdout.encoding=UTF-8 -cp out Main < input.txt"
```

## Идея решения

Хэш вычисляется как `СНИЛС mod размер_таблицы`. Каждая ячейка таблицы хранит
голову односвязного списка; при коллизии новый элемент добавляется в начало
цепочки. При превышении коэффициента заполнения `0.75` создаётся новая
таблица простого размера (примерно вдвое больше), и все элементы переносятся
в неё с пересчётом индексов.
